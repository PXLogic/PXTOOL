# DSView Stream 模式磁盘缓存 — 设计澄清问题

> 状态：待确认  
> 日期：2026-05-18  
> 背景：Stream 模式下采集数据目前全部缓存在内存（`LogicSnapshot` 等），受 `sw_depth`（8/16 GB）限制。拟增加「内存 → 磁盘」的中间层，以提升可采集深度。
>stream 模式：单次和重复模式都是采集固定深度，从头开始显示。滚动模式是以一定深度的数据作为显示取决，类似fifo，只显示fifo内的数据
> 
---

## 现状摘要（供决策参考）

- 数据流：硬件包 → `SigSession::feed_in_logic()` → `LogicSnapshot::append_payload()`
- 内存结构：每通道分层树，leaf block 按需 `malloc`（约 16M samples/block + mipmap）
- Loop 模式已有 `move_first_node_to_last()` / `free_head_blocks()`，但为**丢弃**老数据，非落盘
- 落盘路径：`StoreSession` 在 capture **结束后** 才序列化为 `.dsv`

是否开启硬盘缓存模式是可选的，如果勾选上才使用硬盘缓存，如果没有开启，还是以ram内存进行缓存的。
硬盘缓存可以理解为硬盘是ram的虚拟扩展内存

## Q1【访问模式】采集进行中，对已落盘的老数据怎么访问？

决定整体架构复杂度。

| 选项 | 说明 |
|------|------|
| **A** | **采完再看** — 采集期间视图只看「最近窗口」；往前拖、解码、保存都等 stop 之后。Spill 仅 append-only，实现最简单。 |
| **B** | **边采边翻** — 用户可中途拖回去看历史波形，但解码不动。Spill 需支持随机读，主要来自 UI 线程。 |
| **C** | **边采边翻边解码** — `decoderstack` 也持续从 spill 拼接老数据推给 `srd_session`。I/O 与内存预算要求最严。 |
| **D** | **待定** — 先列出 A/B/C 的实现量、性能、体验差异后再选。 |

**你的选择：** _（单次加选C，重复模式选B，滚动模式选B）_

## Q2【触发策略】什么时候把内存里的数据写到磁盘？

| 选项 | 说明 |
|------|------|
| **A** | **水位线式** — 设内存硬上限（如 sw_depth 的 50%/75%），超过则将最老 leaf block 赶到磁盘并释放内存。 |
| **B** | **总是 spill** — 每个填满的 leaf block 同时写盘；RAM 作为「热窗口 LRU」，老块全在磁盘。深度最大，I/O 压力最高。 |
| **C** | **手动阈值** — UI 中选「仅 RAM 上限」或「RAM + 磁盘上限」两档，明确切换策略。 |
| **D** | **替换 sw_depth 语义** — 原 sw_depth（8/16 GB）变为 RAM 热区上限；新增 `disk_depth`（可达 TB 级）为实际采样深度，超 RAM 限自动落盘。 |

是否开启硬盘缓存模式是可选的，如果勾选上才使用硬盘缓存，如果没有开启，还是以ram内存进行缓存的。
硬盘缓存可以理解为硬盘是ram的虚拟扩展内存

**你的选择：** _（D）_

## Q3【磁盘格式与压缩】Spill 文件怎么组织？

| 选项 | 说明 |
|------|------|
| **A** | **原始 leaf block + 索引** — `(channel, block_index) → file_offset` 追加写入，单文件或多文件；实现最简单、读写最快。 |
| **B** | **每通道一文件** — 每通道独立 spill 文件 + sample 起始偏移表；多通道稀疏访问时随机读更友好。 |
| **C** | **DSV 原生格式** — 复用/对齐现有 `ZipMaker` chunk 格式，边采边写；stop 后可直接 seal 为 `.dsv`（与 Q4-B 配合）。 |
| **D** | **压缩层（后期）** — 在 A/B/C 任一容器上叠加 zstd/RLE；首版可不做，作为扩展项。 |

**你的选择：** _（B或者C看性能能哪个能做得更好，读写速度为先）_

## Q4【生命周期与 .dsv 关系】Spill 文件 stop 之后怎么办？

| 选项 | 说明 |
|------|------|
| **A** | **临时文件** — 采集结束或退出时删除；保存仍走现有 `StoreSession`（可能需从 spill 读回再序列化）。 |
| **B** | **可提升为 .dsv** — Spill 即 `.dsv` 兼容格式；点「保存」仅 rename/seal，零拷贝（通常要求 Q3 选 C）。 |
| **C** | **会话持久化** — Spill 作为 project 级工作文件，下次启动可重载（复杂度高，当前产品无此能力）。 |
| **D** | **用户可选** — 默认 A；UI 提供「边采边存」开关启用 B。 |

**你的选择：** _（A）_

## Q5【适用范围 + Loop 交互】覆盖哪些数据类型？与 loop 模式如何交互？

| 选项 | 说明 |
|------|------|
| **A** | **仅 Logic，不动 loop** — 只给 `LogicSnapshot` 加 spill；loop 仍丢头不落盘。范围最小。 |
| **B** | **Logic + Analog + DSO** — 三种 snapshot 均接 spill；loop 仍丢头。 |
| **C** | **Logic + Loop 先刷盘再丢头** — Loop 在覆盖前先把即将丢弃的块写入磁盘，stop 后可保留「完整历史」。需改 ring 语义。 |
| **D** | **全部** — Logic + Analog + DSO + Loop 均 spill；功能最全，工作量最大。 |

C的选项是否可以都是写入硬盘，loop可以不进行覆盖，而是记录中间区域显示的起始地址，这样就不用重复进行把数据写入覆盖

**你的选择：** _（C）_
